# نشر المشروع على GitHub Pages

هذا المجلد يحتوي موقعًا ثابتًا جاهزًا (index.html + bundle.js) لا يحتاج أي خطوة بناء (build) — GitHub Pages يقدر يعرضه مباشرة.

## خطوات النشر

1. أنشئ مستودع (repository) جديد على GitHub، أو استخدم مستودعك الحالي.
2. ارفع الملفين `index.html` و `bundle.js` في **جذر** المستودع (وليس داخل مجلد فرعي)، إلا إذا كنت تخطط تستخدم مجلد `docs/`.
3. من إعدادات المستودع: Settings → Pages.
4. تحت "Build and deployment" اختر Source: **Deploy from a branch**.
5. اختر Branch: `main` (أو الفرع الذي رفعت عليه الملفات) والمجلد: `/ (root)`.
6. احفظ، وانتظر دقيقة أو اثنتين حتى يظهر رابط الموقع.

## سبب ظهور خطأ 404 سابقًا

خطأ "File not found" من GitHub Pages يعني عادة واحد من الآتي:
- ما فيه ملف `index.html` في جذر المستودع أو في المسار الذي تشير له إعدادات Pages.
- تم رفع ملف `.jsx` مباشرة (كود React مصدري) بدون تجميعه (bundling) — والمتصفح لا يستطيع تشغيل JSX مباشرة، فـ GitHub Pages لا يعرف كيف يخدمه كصفحة.
- اسم الملف أو حالة الأحرف (case) غير مطابقة تمامًا لما في الرابط.

هذا المجلد يحل المشكلة لأنه يحتوي `index.html` حقيقي بالإضافة إلى `bundle.js` الذي يحتوي React وكل المكتبات (lucide-react, recharts) والتطبيق نفسه مُجمّعة في ملف واحد جاهز للمتصفح مباشرة — بدون أي خطوة بناء إضافية على جهازك أو على GitHub.

## إذا أردت تعديل الكود لاحقًا

الملف المصدري لكود React موجود في `src/App.jsx` (إن كان مرفقًا معك في نفس الحزمة). بعد أي تعديل تحتاج تعيد التجميع (bundle) قبل الرفع، لأن `bundle.js` هو نسخة مُجمّعة وليست الكود القابل للتعديل مباشرة.
